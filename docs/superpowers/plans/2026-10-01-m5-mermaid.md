# Milestone 5 — Mermaid Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A fenced `mermaid` code block is drawn as its diagram while the caret is elsewhere, in Focal's colors for the current appearance, and shows its source with a live preview while edited.

**Architecture:** `merman` (a headless, Mermaid-faithful Rust renderer) turns the block's source into resvg-safe SVG, themed from Focal's palette, on GPUI's background executor; results are cached by source and appearance. The block is an island like display math: `IslandKind::Diagram`, rendered as an SVG image sized from its `viewBox` to fit the column, oversampled for Retina. A spike (2026-10-01) compared `merman` 0.7.0 with `mermaid-rs-renderer` 0.3.1: `merman` matched Mermaid's layout, took a host theme, rendered in under 10 ms (1 ms warm) and reported parse errors; the other routed edges poorly and ignored themes. This replaces the design's proposed hidden web view.

**Tech Stack:** `merman` 0.7.0 (`render` feature), GPUI `img()` with SVG images, the island pattern from Milestone 4.

**Spec:** [`docs/design.md`](../../design.md) section 7 (Mermaid row) and section 1 (no web views except an isolated Mermaid renderer — not needed now).

## Global Constraints

- The source stays in the file untouched; a diagram never rewrites it.
- No web view: rendering is native Rust.
- Diagrams follow the light and dark appearance (cached per appearance).
- `mise run check` passes; logic tested in `focal-core` and with UI tests.
- Branch `m5-mermaid`; conventional commits; `mise run clean` when done.

## Review Focus

1. **A malformed diagram while typing**: the preview shows the parser's message; nothing panics and the last good picture is not shown as current. Task 2 tests an error.
2. **A huge diagram**: scaled down to the column and the image height cap. Task 2 sizes from the `viewBox` with the image fit function.
3. **Switching appearance**: the diagram re-renders in the new palette. Task 2 keys the cache by appearance.

---

### Task 1: Find Mermaid blocks (`focal-core`)
`blocks::diagram_blocks(analysis, text) -> Vec<DiagramBlock { lines, source }>` for fenced code blocks whose language is `mermaid` (case-insensitive), `source` being the lines between the fences. Test: a mermaid block, another language, an unclosed fence at the end.

### Task 2: Render and show diagrams
`diagram.rs`: `render(source, palette) -> Result<String, String>` with `merman`, a host theme built from Focal's `Theme`; `svg_size(svg) -> Option<(f32, f32)>` from the `viewBox`; oversampled sizing. Island `IslandKind::Diagram` (via `islands()`), preview after the closing fence while editing, background rendering with a cache keyed by source and appearance, errors as a quiet note. Tests: render a flowchart; a parse error message; island and preview elements in a UI test.

### Task 3: Docs, showcase, decision, manual pass
Proposed decision "Render Mermaid natively with merman"; design section 7 Mermaid row and section 8 (M5 done); README; showcase diagram; `mise run check`; manual pass in both appearances; `mise run clean`.
