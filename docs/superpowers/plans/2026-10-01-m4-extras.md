# Milestone 4 — Extras Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Markdown extras behave, not only look right: links and wiki links open (or create) their files, footnotes preview on hover and jump with a way back, front matter collapses to a quiet summary, images show inline, display math is typeset, and alerts carry icons.

**Architecture:** Resolution and lookup logic (wiki-link targets, footnote definitions, front matter fields, image and math blocks) lives in `focal-core` as pure functions over the analysis and text. The app adds "islands" the way tables already work: a block that takes the place of its source lines while the caret is elsewhere (front matter, block images, display math) and shows its source once the caret enters. Navigation (⌘-click on links and footnotes) records where the caret was, so ⌘[ returns. Remote images are fetched in the background into `~/Library/Caches/Focal`; display math is typeset to SVG by the renderer chosen in Task 5 and cached by content and appearance.

**Tech Stack:** Rust, `pulldown-cmark` 0.13 (wiki links, footnotes, math, metadata blocks), GPUI `img()` with in-memory and file images, the math renderer chosen in Task 5.

**Spec:** [`docs/design.md`](../../design.md) section 7 (extras, Agreed scope), section 4 (embedded views), section 3 (folder mode: wiki links resolve against the folder), section 10 (math renderer, open).

## Global Constraints

- The file is the document: islands never change the source; opening and saving an unedited file keeps its bytes.
- Wiki links `[[name]]` and `[[name|label]]` resolve to files in the open folder (or, for a single file, its folder); unresolved links look different; ⌘-click opens or creates (design 7).
- Footnotes: references show as quiet raised-looking numbers; hovering previews the note; clicking jumps and "back" returns (design 7). GPUI text runs cannot change size or baseline within a line, so references stay inline styled text.
- Images: relative paths resolve against the document; remote images load asynchronously with a cache; images scale to the column width (design 7).
- Math: inline math stays styled source inside its line (GPUI cannot place an element inside a text run); display math (`$$ … $$` blocks) is an island.
- No web views (design principle "Native first").
- `mise run check` passes after every task; logic in `focal-core` with unit tests; UI behavior with headless UI tests.
- Work on branch `m4-extras` in `.worktrees/rust-gpui`; conventional commits with the session's `Co-Authored-By` line; `mise run clean` when done.

## Review Focus

1. **A wiki link whose name matches files in two folders, or differs only in case**: the nearest match by path wins deterministically (same folder first, then shortest path), and creating never overwrites. Task 1 tests ambiguity and case.
2. **Moving the caret into an island with the arrow keys**: front matter, images and display math show their source and the caret lands on the first or last source line, as tables do. Tasks 3 to 5 test entering from above and below.
3. **An image that fails to load (missing file, 404, not an image)**: the line shows its source with a quiet "image not found" note; nothing hangs or panics. Task 4 tests a missing file.
4. **⌘[ with nothing to go back to, or after the document changed**: nothing happens, or the caret lands at the clamped old position. Task 2 tests both.
5. **A footnote reference whose definition is missing**: no preview, no jump, no crash. Task 2 tests it.

### Task 1: Links and wiki links open their targets

- Core `links.rs`: `wiki_target(name: &str) -> (String, Option<String>)` (name and label split on `|`, `#heading` dropped); `resolve_wiki(name, from_dir, files: &[PathBuf]) -> Option<PathBuf>` (case-insensitive stem or relative path match; same folder first, then shortest path); `relative_target(destination, document_dir) -> Option<PathBuf>` for local Markdown links (percent-decoded, `#fragment` dropped).
- App: ⌘-click on a wiki link or a local Markdown link opens the file — in folder mode in the same window (saving first), otherwise as a new window through `windows::open`; an unresolved wiki link creates `<name>.md` beside the document and opens it. Unresolved wiki links render in the marker color with a dotted underline. ⌘-click on `#heading` links moves the caret to that heading. Every jump pushes the previous selection on a back stack; `GoBack` (⌘[) returns.
- Tests: core resolution (case, ambiguity, label, heading suffix, percent-encoding); UI: ⌘-click a wiki link in folder mode opens the file; an unresolved one creates it; ⌘[ returns; ⌘[ with an empty stack does nothing.

### Task 2: Footnotes preview and jump

- Core: `footnotes(analysis/text) -> Vec<Footnote { label, references: Vec<Range>, definition: Option<Range> }>` from `pulldown-cmark`'s footnote events; `footnote_at(offset)`.
- App: hovering a reference shows a small popover with the definition's text (markers hidden) near the pointer; ⌘-click on a reference jumps to its definition, on a definition label jumps to the first reference; both push the back stack.
- Tests: core lookup with missing definitions; UI: hover shows the preview element; ⌘-click jumps and ⌘[ returns; a missing definition shows nothing.

### Task 3: Front matter collapses

- Core: `front_matter(analysis, text) -> Option<FrontMatter { lines, fields: Vec<(String, String)> }>` (simple `key: value` lines; others shown raw).
- App: while the caret is outside it, front matter is one quiet row of `key value` pairs; a click or the caret entering (arrows) shows the source. A newly opened document places the caret at the start of the body, after front matter.
- Tests: core field parsing (lists, quoted values, nested lines skipped); UI: collapsed on open with the caret after it; up from the first body line shows the source.

### Task 4: Images

- Core: `block_image(analysis, text, line) -> Option<ImageRef { alt, destination }>` for a line that holds only an image.
- App: such a line renders the image (scaled to the column, at most its natural size, with rounded corners) while the caret is elsewhere; the caret on the line shows the source with the image below it. Local paths resolve against the document's folder; `http(s)` images are fetched once in the background with macOS's `curl` into `~/Library/Caches/Focal/images/<hash>` and shown when ready; failures show a quiet note.
- Tests: core detection (image alone, image with text, image inside a link); UI: a local image line renders an image element; the caret on it shows the source; a missing file shows the note.

### Task 5: Display math

- Spike: typeset LaTeX math to SVG natively. Candidates: Typst with `mitex` (LaTeX to Typst math), a pure-Rust LaTeX math renderer, or MathJax in an embedded JavaScript engine (no web view). Choose by output quality, coverage of common LaTeX, speed per formula (cached) and binary size; record a proposed decision.
- App: a `$$ … $$` block renders as a centered SVG island in the text color while the caret is outside, with source and a live preview below while editing; results cached by source hash and appearance; errors show the source with a quiet message.
- Tests: renderer unit tests (simple formula renders, invalid input errors); UI: a display math block renders an image element; entering it shows the source.

### Task 6: Alert icons, docs and manual pass

- Alerts get a small icon before their title (Note ⓘ, Tip ✦, Important !, Warning ⚠, Caution ⊘) in the alert color.
- Showcase gains examples (wiki link, footnote preview, image, display math); `docs/design.md` section 7 and 8 (M4 done) and section 10 (math renderer) updated; README status.
- `mise run check`, manual pass of every feature in both appearances, commit, `mise run clean`.
