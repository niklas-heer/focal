# Milestone 10 — Diagrams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Diagrams in the languages Markdown files use draw in place, like Mermaid already does: Graphviz, Svgbob, Pikchr, WaveDrom, GeoJSON and TopoJSON natively, D2 and PlantUML through their tools when installed, every Mermaid diagram type checked.

**Architecture:** `focal-core::blocks` recognizes a fenced block's diagram language (`DiagramLanguage`, with each language's aliases). The app's `diagram.rs` becomes a dispatcher: Mermaid through merman as before, Graphviz through `layout-rs` (or the `dot` tool when installed, which handles all of DOT), Svgbob through `svgbob`, Pikchr through `pikchr`, WaveDrom through `wavedrom`, GeoJSON and TopoJSON through a small projection of their outlines, D2 and PlantUML through their command-line tools. Every renderer's SVG goes through one recolor step into Focal's palette (light and dark) and fonts. A block whose language cannot be drawn here (its tool is missing) stays a code block. Rendering runs on the background executor and is cached by language, source and palette, as Mermaid is.

**Tech Stack:** Rust, `layout-rs` 0.1, `svgbob` 0.7, `pikchr` 0.1 (C library, built by `cc`), `wavedrom` 0.1, `serde_json`; optional tools `dot`, `d2`, `plantuml`.

**Spec:** [`docs/design.md`](../../design.md) section 7a, the Diagrams table, and its principles ("native first; tools the user installed are used when present; no network services unless the user opts in").

## Global Constraints

- The file is the document: diagrams are drawn, never written back.
- Native renderers first; external tools only when found on `PATH` (and Homebrew's `/opt/homebrew/bin`, which apps launched from Finder do not see); a tool runs with a timeout and its errors show as the diagram's message.
- No network: Kroki and similar services are not used.
- A language Focal cannot draw on this Mac keeps its code block; nothing is hidden behind a placeholder.
- Every diagram follows the appearance (light and dark) through the shared recolor step.
- `mise run check` after every task; `focal-core` logic with unit tests; renderers with unit tests that render a small diagram each; UI tests for islands.
- Branch `m10-diagrams`; conventional commits with the session's `Co-Authored-By` line; `mise run clean` at the end.

## Review Focus

1. **A diagram that fails to parse** (bad DOT, broken WaveDrom JSON): shows the renderer's message under the source, like Mermaid. Task 2 and 3 test one each.
2. **A tool that hangs or is slow** (`plantuml` starting a JVM): times out after a few seconds with a message; Focal never blocks. Task 4 tests the timeout with a fake tool.
3. **Dark mode**: no black text on the dark background in any renderer. Task 2 tests that recolored SVG contains no pure black or white.
4. **A huge GeoJSON file**: drawn with its outlines simplified, within the island's height. Task 3 tests a large polygon.
5. **Export**: every drawn language exports as SVG (and as a picture for Copy as HTML). Task 1 changes the export callback and tests it.

---

### Task 1: Diagram languages and the dispatcher
- Core: `DiagramLanguage` (`mermaid`; `dot`, `graphviz`, `gv`; `svgbob`, `bob`; `pikchr`; `wavedrom`; `plantuml`, `puml`; `d2`; `geojson`; `topojson`), `diagram_blocks` returns every block with its language; export's `Embed::Diagram` carries the language.
- App: `diagram::render(language, source, palette)`, `diagram::can_draw(language)`; islands cache by language; only drawable languages are islands.
- [ ] Tests: language aliases; a `dot` block is a diagram block; a `plantuml` block without the tool stays a code block; export passes the language.

### Task 2: Graphviz, Svgbob and Pikchr, and the recolor step
- `recolor(svg, palette, font)`: black and white (named, hex with or without alpha, `rgb()`) become the palette's text, line and surface colors; text without a fill gets the text color; fonts become Focal's.
- Graphviz: `dot -Tsvg` when found, else `layout-rs`. Svgbob and Pikchr natively.
- [ ] Tests: each renders a small diagram to SVG; a DOT syntax error gives a message; recolored dark SVG has no `#000`/`black`/`#fff`/`white`.

### Task 3: WaveDrom, GeoJSON and TopoJSON
- WaveDrom JSON through `wavedrom`; GeoJSON (Feature, FeatureCollection, geometries) and TopoJSON (arcs decoded, quantized or not) projected equirectangularly into an outline map in the palette, simplified to a point budget.
- [ ] Tests: a WaveDrom signal; a GeoJSON polygon and point; a TopoJSON object; a large polygon stays within the budget; broken JSON gives a message.

### Task 4: D2 and PlantUML through their tools
- Tool lookup on `PATH` plus `/opt/homebrew/bin` and `/usr/local/bin`, cached; run with stdin and a 10-second timeout; D2 with a theme for the appearance; PlantUML `-tsvg -pipe`.
- [ ] Tests: lookup finds a fake tool in a temp folder; a fake tool that sleeps times out with a message; D2 renders when installed (skipped otherwise).

### Task 5: Mermaid coverage, showcase and docs
- A corpus of every Mermaid diagram type (flowchart, sequence, class, state, ER, journey, gantt, pie, quadrant, requirement, git graph, C4, mindmap, timeline, sankey, XY chart, block, packet, kanban, architecture, radar, treemap) rendered by merman in a test that reports which fail; failing types show the parser's message (already) and are recorded in the design.
- `examples/diagrams.md`, design table statuses, README; `mise run check`; manual pass; merge, push, clean.
