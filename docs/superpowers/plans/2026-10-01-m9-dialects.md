# Milestone 9 — Dialects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Whatever Markdown dialect a file was written in, Focal shows it well: other math delimiters, every callout and admonition style, more front matter formats, the Pandoc/Extra extensions, Obsidian's syntax, emoji shortcodes, tables of contents, common raw HTML, and files in other encodings.

**Architecture:** A **shadow text** (`focal-core/src/shadow.rs`): an equal-length copy of the source in which other dialects' syntax is rewritten into what `pulldown-cmark` already understands (`\(`→` $`, `!!! note`→`>[!note]`, a `:::` fence line→spaces). Because every byte keeps its offset, the analysis, outline and export parse the shadow while styling, markers and editing keep working on the untouched source. What cannot be expressed that way (callout regions without `>`, abbreviations, comments, tags, emoji, TOC lines, HTML tags) is found by small passes over the source, outside code. Encodings are handled when a file is read and written (`document.rs`, `encoding_rs`).

**Tech Stack:** Rust, `pulldown-cmark` 0.13 options (superscript, definition lists, heading attributes, `+++` metadata), `encoding_rs`, `emojis` (GitHub shortcodes).

**Spec:** [`docs/design.md`](../../design.md) section 7a (Compatibility, the Dialects table and the raw HTML policy).

## Global Constraints

- The file is the document: no construct is rewritten in the file; opening and saving an unedited file keeps its bytes, also in UTF-16 or Windows-1252.
- The shadow text has the same length as the source and changes only bytes outside code spans and code blocks.
- Unrecognized syntax shows as source; nothing that rendered before renders worse (all existing tests stay green).
- Subscript `~x~` stays strikethrough (GitHub's reading); `^x^` is superscript.
- The editor never runs HTML; export applies GFM's tagfilter.
- `mise run check` passes after every task; logic in `focal-core` with unit tests; UI behavior with headless UI tests.
- Branch `m9-dialects` in `.worktrees/rust-gpui`; conventional commits with the session's `Co-Authored-By` line; `mise run clean` at the end.

## Review Focus

1. **Dialect syntax inside code** (`\(` in a code span, `!!! note` in a fenced block): never rewritten or styled. Task 1 tests code spans and fences.
2. **An unclosed container** (`::: note` with no closing `:::`): runs to the end of the document like Docusaurus, without hiding text. Task 2 tests it.
3. **A file that is neither UTF-8 nor UTF-16** (a Windows-1252 note with `é`): opens readable and saves back byte-identical when unedited. Task 6 tests the round trip.
4. **Emoji-like text that is not a shortcode** (`10:30:00`, `std::io`): left alone. Task 4 tests times and Rust paths.
5. **HTML that only looks like a supported tag** (`<b` unclosed, `<img` inside a paragraph with text): stays source. Task 5 tests both.

### Task 1: The shadow text, and math in every notation

**Files:** Create `crates/focal-core/src/shadow.rs`; modify `analysis.rs` (parse the shadow), `outline.rs`, `export.rs`, `blocks.rs` (math fences), app `islands.rs` if needed.

- `pub fn shadow(text: &str) -> Cow<str>`: same length; skips fenced code (`` ``` ``/`~~~`, except `` ```math ``) and code spans. Rewrites: `\(`/`\)` → ` $`/`$ `; `\[`/`\]` → `$$`; `` $` ``/`` `$ `` → ` $`/`$ `; a `` ```math `` fence → `$$` padded with spaces, its closing fence → `$$` padded.
- The analysis hides `\(`, `\)`, `\[`, `\]`, the backtick forms and the math fences as markers; display math from any notation is an island.
- [ ] Tests: each notation becomes math (inline unicode replacement, display island); code spans and fences untouched; length equality as a property over the test inputs; export renders all notations as math.

### Task 2: Callouts in every style

**Files:** Modify `analysis.rs` (callout kinds and titles, `PrefixLevel::Block`), `shadow.rs`, `prefix.rs` (draw block bars), `display.rs` if needed, `export.rs`.

- `Alert` gains every Obsidian type mapped to the five colors (info/todo/abstract/summary/tldr → Note; tip/hint/success/check/done → Tip; important/question/help/faq/example → Important; warning/attention → Warning; caution/danger/error/bug/failure/fail/missing → Caution; quote/cite → plain quote) and the title written after `]` (else the type's name). `+`/`-` fold markers are hidden.
- `::: type Title` … `:::` (also `:::type`, `:::type[Title]`, `::: {.type}`, nested with more colons) and GitLab `>>>` … `>>>`: the shadow blanks the fence lines; lines inside get a `Block` prefix level drawn as a bar in the callout color; the opening fence shows the title like an alert.
- `!!! type "Title"` / `??? type` / `???+ type`: the shadow writes `>[!type]` (same length) and turns each body line's four-space indent into `>   `; the callout spans the title and its indented body, blank lines included.
- [ ] Tests: Obsidian custom type with title and fold; container with title, nested container, unclosed container; `>>>`; MkDocs admonition with two paragraphs; export renders each as an alert block.

### Task 3: Front matter, Pandoc and Extra extensions

**Files:** `analysis.rs`, `shadow.rs`, `blocks.rs` (front matter fields for TOML and JSON), `export.rs`.

- Front matter `+++` (TOML) and `;;;` (JSON, shadowed to `---`); fields read for the collapsed line (`key = value`, `"key": value`).
- Superscript `^x^` (Unicode superscript when every character has one, otherwise a raised style), definition lists (term bold, `: ` hidden), heading attributes `{#id .class}` hidden away from the caret, abbreviation definitions `*[X]: …` as quiet lines.
- [ ] Tests for each, and export.

### Task 4: Obsidian syntax, emoji and tables of contents

**Files:** `analysis.rs`, `links.rs`, `blocks.rs`, app `islands.rs` (TOC island), `export.rs`, `Cargo.toml` (`emojis`).

- `![[image.png]]` (and `|width`) is an image resolved like a wiki link (anywhere in the folder); `![[note]]` is a link to the note. `%%comment%%` (also multi-line) and HTML comments are quiet. `#tag` and `#tag/sub` (not headings, not inside words or URLs) are styled.
- `:shortcode:` with a known GitHub shortcode shows its emoji away from the caret; times (`10:30:00`) and paths (`std::io`) are left alone.
- A line holding only `[TOC]`, `[[_TOC_]]`, `[[toc]]` or `{:toc}` (with an optional `* TOC` line above) is an island listing the outline; clicking an entry moves there.
- [ ] Tests for each, and export (embeds as `<img>`, comments dropped, tags as text, emoji as characters, TOC as a nested list).

### Task 5: Raw HTML

**Files:** Create `crates/focal-core/src/html_inline.rs`; modify `analysis.rs`, `blocks.rs` (`<img>` alone is a block image), `export.rs` (tagfilter).

- Inline tags `b strong i em u ins s del strike mark kbd sub sup code a br` with matching closing tags style their content and hide the tags away from the caret; `<br>` shows as a line break mark. `<img src=…>` alone on its line (also wrapped in `<p align>`/`<div align>`/`<center>` lines) is an image island honoring `width`. Wrapper lines are quiet. `<details>`/`<summary>`: the summary line shows as a callout-like title. Everything else unchanged.
- Export: GFM tagfilter (`title textarea style xmp iframe noembed noframes script plaintext` → `&lt;tag`).
- [ ] Tests: each tag, an unclosed `<b`, `<img>` mid-sentence stays source, README-style centered logo is an image, export tagfilter.

### Task 6: Encodings and line endings

**Files:** `document.rs`, `Cargo.toml` (`encoding_rs`), `lines.rs` (CR).

- Reading: UTF-8 (BOM kept), UTF-16 LE/BE (BOM), otherwise Windows-1252 when the bytes are not UTF-8. The document remembers the encoding and BOM and writes with them; a character the encoding cannot hold switches the file to UTF-8 and says so in the banner.
- Line endings: a lone CR ends a line (old Mac files); kept on save.
- [ ] Tests: round trip for each encoding unedited (byte-identical) and edited; CR-only files have lines; the bar or banner names a non-UTF-8 encoding.

### Task 7: Showcase, docs and manual pass

- `examples/dialects.md` exercising every construct; design table statuses; README; `mise run check`; manual pass in both appearances; merge, push, clean.
